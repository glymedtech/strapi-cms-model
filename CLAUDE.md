# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Strapi 5.53 headless CMS (JavaScript, CommonJS) that holds the content model for the Glymed website. The repo is essentially a **content-model definition**: almost all substance lives in JSON schemas, not custom code. No tests or linter are configured.

## Commands

Yarn is the package manager (`yarn.lock`). Node >=20.

- `yarn develop` — run with auto-reload (needed when creating/editing content types via the admin Content-Type Builder, which writes schema files)
- `yarn start` — run without auto-reload
- `yarn build` — build the admin panel
- `yarn seed:example` — starter-template seeder (`scripts/seed.js`); **stale**: it targets article/category/author/global/about types that don't exist here and is intentionally not wired into `src/index.js`

Setup: copy `.env.example` to `.env` (secrets are placeholders). The DB defaults to SQLite (`.tmp/`); `config/database.js` switches to mysql/postgres via `DATABASE_CLIENT` and `DATABASE_*` env vars.

## Architecture

- `src/api/<name>/` — one folder per content type, each with `content-types/<name>/schema.json`, plus `controllers/`, `routes/`, `services/`. The controller/route/service files are unmodified boilerplate (`createCoreController/Router/Service`); **real changes go in `schema.json`**. Only edit the JS files when adding genuinely custom behavior.
- `src/components/shared/*.json` — reusable components (banner, faq, list, text-with-color, product-card, etc.) referenced from schemas as `shared.<name>`.
- Content types fall into groups by naming: `*-page` (page-level content such as home, blog-page, education-page, product-page, webinar-page), and entity collections (blog, regimen, protocol, webinar, instructor-team-member, calendar-*, etc.). Several are single types; most are collection types with `draftAndPublish` on.
- Pages are often audience-specific: e.g. `home` is a collection type with a required `role` enumeration (`pro`, `retail`, `school`, `web`), so there is one entry per audience rather than a single type.
- `types/generated/` — auto-generated TS typings (`components.d.ts`, `contentTypes.d.ts`) regenerated by Strapi on run/build; don't hand-edit. Commit them alongside schema changes.
- `config/` — standard Strapi config; `plugins.js`, `middlewares.js` are near-default. Installed community plugins: color-picker, multi-select, timezone-select.
- `src/index.js` (register/bootstrap) and `src/admin`, `src/extensions` are empty/example stubs.
- `database/migrations/` is empty; `.tmp/` (SQLite) and `.env` are gitignored.

## Workflow

Work happens on ticket-named feature branches (e.g. `gl-6216-HomePage-HM`) merged into `main` via PRs.
